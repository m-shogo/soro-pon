# Match Layout and Orientation

## Purpose

4人対戦、牌の見やすさ、捨て牌の見やすさ、操作のしやすさを優先するため、対戦画面の向きを決める。

結論:

```text
対戦画面はスマホ横向き前提で設計する。
TOP / デッキ作成 / 役編集 / リザルトは縦でも使えるレスポンシブ設計にする。
```

## Why Landscape for Match

soro-ponの対戦画面には、同時に表示すべき情報が多い。

- 自分の手牌 8〜9枚
- 将来拡張では13〜14枚
- 相手3人の状態
- 捨て牌
- 山
- 現在ターン
- ツモ/捨てる/あがる/ロン表示
- 役候補
- 特殊役/ボーナス情報
- オールマイティ使用表示

スマホ縦画面で無理に全部入れると、牌か捨て牌が小さくなりすぎる。

そのため、対戦画面は横向き前提にする。

## Target Viewport

基準サイズ:

```text
844 x 390
```

想定:

- スマホ横向き
- ブラウザゲーム
- Safe areaあり
- 片手だけでなく両手持ち操作を前提

縦向き時は、対戦画面を無理に表示しない。

```text
端末を横向きにしてください
```

という案内を出す。

## Browser Reality

ブラウザでは、端末の向きを完全に固定できない場合がある。

そのため実装方針は以下。

- CSS/viewportで横向きレイアウトを最適化する
- portrait時は横向き案内を表示する
- fullscreen/orientation lockは後回し
- PWA化もMVPでは不要

## Screen Orientation Policy

### Portrait-friendly Screens

以下は縦画面でも使えるようにする。

- TOP
- デッキ一覧
- デッキ作成
- 牌編集
- 上がり役編集
- 特殊役編集
- ボーナス編集
- JSON import/export
- ルール確認
- リザルト

### Landscape-first Screens

以下は横向き前提にする。

- 対戦準備の最終確認
- 対戦画面
- 対戦中の役表確認
- 対戦中のロン/あがり確認

## Match Screen Layout

麻雀アプリの見やすさを参考にする。

そのまま麻雀UIに寄せすぎる必要はないが、以下の考え方は使う。

- 相手情報は上/左右に寄せる
- 自分の手牌は下部に大きく並べる
- 捨て牌は中央にまとめる
- 山やターン表示は中央上寄り
- 重要アクションは右下〜下部に置く
- 役候補は常時大きく出さず、必要なときだけ小さく表示/開閉する

## Recommended Landscape Layout

```text
┌──────────────────────────────────────────┐
│              Opponent Top                │
│       name / hand count / discards       │
├───────────────┬───────────────┬──────────┤
│ Opponent Left │   Table Area  │ Opp Right│
│ mini panel    │ discards      │ mini     │
│               │ deck/status   │ panel    │
├───────────────┴───────────────┴──────────┤
│              My Hand 8〜9 tiles           │
│      [tile][tile][tile][tile]...          │
├──────────────────────────────────────────┤
│ Candidate / Message       Action Buttons │
│ あと1枚 / 成立役候補        ツモ 捨てる あがる │
└──────────────────────────────────────────┘
```

## My Hand Area

自分の手牌は画面下部に配置する。

### Standard Rule

- 通常8枚
- 引いた後9枚
- 横一列で表示できるなら横一列
- 名前が読めない場合は2段も許可

### Extended Rule

- 通常13枚
- 引いた後14枚
- 横一列は厳しいため2段表示を前提にする
- 13〜14枚でも牌名が読めるサイズを優先

## Tile Visibility

牌はゲーム体験の主役。

必須:

- 牌の画像/絵文字が見える
- 牌名が読める
- オールマイティが一目で分かる
- 選択中の牌が分かる
- 捨てられる牌が分かる
- ロン/あがり対象が分かる

避ける:

- 牌が小さすぎる
- 名前が省略されすぎる
- 画像だけで名前が分からない
- 色だけでカテゴリ判定させる

## Discard Visibility

捨て牌は、麻雀アプリの河のように見やすく配置する。

ただし、soro-ponは牌名・画像・カテゴリが重要なので、麻雀牌より少し大きく見せる。

表示するもの:

- 誰が捨てたか
- 直近の捨て牌
- 各プレイヤーの捨て牌枚数
- ロン対象になった捨て牌

優先:

1. 直近の捨て牌
2. 自分がロンできる可能性のある捨て牌
3. 各プレイヤーの捨て牌履歴

## Opponent Panels

相手は最大3人。

表示するもの:

- 名前
- CPU/human
- 手牌枚数
- 捨て牌枚数
- 現在ターン
- リーチ状態（将来）

表示しないもの:

- 相手の手牌内容
- 大きすぎるアバター
- 長文説明

## Action Area

主要ボタン:

- ツモ/引く
- 捨てる
- あがる
- ロン
- パス
- 役表

配置:

- 右下〜下部
- 親指で押しやすい位置
- 誤タップしにくいサイズ

ボタン状態:

- 押せる
- 押せない
- 注意
- 強調

を明確にする。

## Role Candidate Display

役候補は常時大きく出さない。

理由:

- 画面を圧迫する
- 捨て牌と手牌が見づらくなる
- 候補が多いと情報過多になる

表示方針:

```text
小さな候補バー
または
開閉式パネル
```

表示するもの:

- あと1枚の上がり役
- 現在成立している上がり役
- ロン可能時の役名
- 特殊役/ボーナスは結果計算時に主表示

## Ron UI

ロン候補は増やしすぎない。

ルール:

- ロン判定は `win_role` のみ
- `special_bonus` はロン候補にしない
- `score_bonus` はロン候補にしない
- 捨てられたオールマイティでロンは原則不可

UI:

```text
ロンできます: 役名
[ロン] [パス]
```

複数役でロン可能な場合:

- 最も高い上がり役を優先表示
- 詳細は開閉で見る
- 画面を埋めない

## Result Screen Orientation

リザルトは縦でも横でもよい。

ただし、対戦直後は横向きのまま表示される可能性が高いので、横向きでも見やすくする。

表示するもの:

- 勝者
- 上がり役
- 特殊役
- スコアボーナス
- オールマイティ使用
- 合計点
- もう一局
- デッキ調整

## Review Checklist

対戦画面デザインを採用する前に確認する。

- 4人対戦に見えるか
- 自分の手牌が一番見やすいか
- 8〜9枚が自然に収まるか
- 13〜14枚拡張に耐えられるか
- 捨て牌が見やすいか
- 直近の捨て牌が分かるか
- ロン/ツモ/捨てるが押しやすいか
- 役候補が邪魔していないか
- オールマイティが分かるか
- 特殊役/ボーナスがロン候補になっていないか
- 縦向き時に破綻せず横向き案内が出るか

## Final Decision

- 対戦画面は横向き前提
- 縦向きで無理に対戦画面を作らない
- TOP/Editor/Resultは縦対応もする
- ブラウザゲームなのでorientation lockには依存しない
- portrait時は横向き案内を出す
- 麻雀アプリの情報配置を参考にしつつ、soro-ponでは牌名・画像・カテゴリの見やすさを優先する
