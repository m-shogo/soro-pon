# IP and UGC Policy

## Basic Position

`soro-pon` は、公式には既存IPに依存しないカスタム牌ゲームとして作る。

ユーザーが自由なテーマでデッキを作れる余地は残すが、公式は既存IP利用を促進しない。

## Local Development

開発中のローカル検証で、分かりやすい題材を使うことはある。

ただし、既存IP由来の検証データは完全にローカル限定。

以下に入れない。

- `src/`
- `public/`
- `docs/`
- `README`
- build成果物
- 公式サンプル
- 公式スクリーンショット
- 共有サンプル

## Do Not Commit

既存IP検証データはgit管理しない。

`.gitignore` で以下を除外する。

```gitignore
dev-fixtures/ip-local/
*.ip-local.json
*.local-deck.json
*.local-fixture.json
```

## Official Samples

公式サンプルは以下を使う。

- 動物
- 国
- 歴史人物
- 旅行
- 食べ物
- 星座
- 都道府県
- オリジナルテーマ

## Officially Prohibited

公式として以下はしない。

- IPデッキ名を紹介する
- IP名ハッシュタグを推奨する
- 人気IPデッキランキングを作る
- IPデッキをアプリ内検索可能にする
- IPデッキの公開ギャラリーを作る
- 画像付きデッキ共有を作る
- 第三者画像アップロードを推奨する
- 「推しキャラで作ろう」と公式文言にする
- IPデッキのスクリーンショットを公式SNSに出す

## User-generated Data

初期MVPでは公開UGC機能を作らない。

ユーザー間の共有は画像なしJSONのみ。

将来公開ギャラリーを作る場合は、以下が必要。

- 通報導線
- 削除申請フォーム
- 禁止ワード/カテゴリ運用
- 権利者対応フロー
- 公開前チェック
- 繰り返し違反ユーザー制限

## Product Wording

使ってよい表現。

```text
好きなテーマで、牌・役・得点を作れるカスタム牌ゲーム。
```

避ける表現。

```text
好きなアニメキャラで作れる
推しキャラで遊べる
有名作品デッキを共有できる
```

## Final Rule

公式はクリーン。  
共有は画像なし。  
画像は各ユーザーの端末だけ。  
既存IP検証データはローカル限定で、公開物には一切混ぜない。
