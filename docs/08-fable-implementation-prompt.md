# Fable Implementation Prompt

このファイルは、実装開始時にFable / Claude Codeへ貼るためのプロンプト。

```text
新規で「soro-pon」というWebゲームを1から作ります。

重要:
- 既存repo・既存コード・既存設計・既存デザインは参考にしない
- 完全新規で作る
- いきなり大きく作らず、小さいコミットで進める
- 実装前に必ず短い設計方針を出す
- その後、最小の1コミットずつ進める
- 各コミット後にテスト結果・変更内容・次の作業を報告する

==================================================
【ゲームの核】
==================================================

ゲーム名:
- soro-pon

ゲームの本質:
- ドンジャラと同じルール感の、絵柄をそろえて役を作る牌ゲーム
- ただし最終プロダクトでは既存IP・既存商品名に依存しない
- このゲームのキーは「プレイヤーが自分でデッキ、牌、役、得点を決められること」
- ただ遊ぶだけでなく、自作ルールで遊べることが最重要

最重要機能:
1. デッキを作れる
2. 牌を作れる
3. 役を作れる
4. 得点を決められる
5. 作った内容でそのまま遊べる
6. 共有用JSONを書き出せる
7. 共有用JSONを読み込める

==================================================
【プレイ人数 / 対戦形式】
==================================================

- 3〜4人用で作る
- 2人用は作らない
- MVPではローカル対戦のみ
- まずは人間1人 + CPU2人 or CPU3人で遊べるようにする
- 3人戦と4人戦の両方に対応する
- オンライン対戦は作らない
- ログイン機能は作らない

==================================================
【牌の仕様】
==================================================

牌は以下の情報を持つ:
- id
- name
- categories: string[]
- image または emoji
- fallbackLabel
- count

重要:
- categories は複数持てる
- image がない場合は emoji
- image も emoji もない場合は fallbackLabel
- 牌の一番下には必ず name を表示する
- 画像がある場合も名前は省略しない
- 共有JSONには画像情報を含めない

表示優先順位:
1. local image
2. emoji
3. fallbackLabel
4. name

==================================================
【役 / 得点】
==================================================

役はユーザーが自作できる。

役は以下の情報を持つ:
- id
- name
- points
- condition
- description optional

最初に対応する役条件:
- contains_all
- same_name_count
- same_category_count
- all_different_categories
- exact_group

後から増やせる設計にする。

==================================================
【デッキの意味】
==================================================

このゲームにおける「デッキ」は以下の意味:

Deck = tile set + roles + scoring rules

つまり:
- その卓で使う牌一覧
- 牌ごとの枚数
- 役一覧
- 役ごとの得点
- ルールセット全体

==================================================
【共有仕様】
==================================================

共有はJSONで行う。

共有JSONに含める:
- deck name
- tile definitions
- categories
- counts
- role definitions
- points
- conditions
- emoji
- fallbackLabel

共有JSONに含めない:
- 画像データ本体
- imageUrl
- 外部画像URL
- base64画像
- remote image
- localImageId
- 他者の画像アセット

画像の扱い:
- 画像は各ユーザーが自分の端末で設定する
- 共有JSONには画像情報を入れない
- export時に画像情報を絶対に含めない
- import時に imageUrl / imageBase64 / remoteImage などが入っていたら、無視するかエラーにする
- ローカル見た目カスタムと共有JSONを分離する

==================================================
【サンプルデッキ / 開発データ】
==================================================

開発初期の検証用:
- ワンピース
- NARUTO

ただし重要:
- これは開発中にゲーム性を確認するためのローカル検証用データ
- src / public / docs / README / build成果物 に既存IPデータを入れない
- git管理しない
- 公式サンプルとして同梱しない
- 共有機能のサンプルとして出さない
- 公式SNS・スクリーンショットにも出さない

最終的な公式サンプル:
- 動物
- 国
- 歴史人物
- オリジナルテーマ

ここは厳守。

==================================================
【技術方針】
==================================================

技術スタック:
- Vite
- React
- TypeScript
- Zustand
- Zod
- Vitest
- localStorage

必須方針:
- ルールエンジンはUIから分離
- App.tsx巨大化を避ける
- 純粋関数を優先
- 型を先に作る
- JSON import/export は schema validate する

==================================================
【MVP画面】
==================================================

1. Home
2. Deck Editor
3. Tile Editor
4. Role Editor
5. Match Screen
6. Result Screen

重要:
- 1画面1目的
- 自分の手牌を主役にする
- 相手3人は小さく表示
- 情報を詰め込みすぎない

==================================================
【実装順】
==================================================

Phase 1:
- 新規プロジェクト作成
- 型定義
- Zod schema
- 最小サンプルデッキ
- 3人戦 / 4人戦の MatchState 初期化
- 山生成
- 配牌
- 引く / 捨てる / ターン進行
- Vitest で基本ロジックのテスト

Phase 2:
- 役判定
- 得点計算
- 勝利判定
- 結果表示
- Vitest 追加

Phase 3:
- Deck Editor
- Tile Editor
- Role Editor
- localStorage 保存

Phase 4:
- JSON export
- JSON import
- 画像情報除外
- import validation
- ローカル画像上書き

==================================================
【禁止事項】
==================================================

- 既存repoを参考にしない
- 既存コードを移植しない
- オンライン対戦を作らない
- ログインを作らない
- Supabaseを入れない
- PWAを作らない
- 実績を作らない
- 公開ギャラリーを作らない
- ランキングを作らない
- 画像付き共有を作らない
- 共有JSONに画像を入れない
- 既存IP検証データを公式物に混ぜない
- いきなり大きく作らない
- 1コミットで大量変更しない

最初の目標:
1. 新規プロジェクト作成
2. 中心型の定義
3. Zod schema
4. 最小サンプルデッキ
5. 3人戦 / 4人戦の初期化
6. 引く / 捨てる / ターン進行
7. Vitest でロジックテスト
```
