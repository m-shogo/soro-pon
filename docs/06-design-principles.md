# Design Principles

## Design Goal

最初のUIは、派手さよりも分かりやすさを優先する。

このゲームは、牌・役・得点を作って遊ぶゲーム。  
そのため、対局画面だけでなく、Editor画面の見やすさも重要。

## Core Principles

### 1. 1画面1目的

1つの画面で複数の目的を持たせない。

- Home: 始める
- Deck Editor: デッキを作る
- Tile Editor: 牌を作る
- Role Editor: 役を作る
- Match: 遊ぶ
- Result: 結果を見る

### 2. 牌を大きく見せる

対局画面では、自分の手牌が主役。

- 相手3人はミニ表示
- 捨て牌や山札は補助表示
- 操作ボタンは分かりやすく
- 牌の下部には必ず名前を出す

### 3. 画像なしでも成立させる

牌の見た目は以下の順で出す。

1. ローカル画像
2. 絵文字
3. fallback label
4. 名前

画像がなくても遊べる状態を必ず保つ。

### 4. 情報を詰め込みすぎない

特にスマホでは以下を避ける。

- 長文説明
- 小さすぎる文字
- 多すぎるラベル
- 複雑な装飾
- 状態が分かりにくい色分け

### 5. Editorを軽視しない

このゲームの主役は「自作」でもある。

重要なEditor:

- Deck Editor
- Tile Editor
- Role Editor
- Scoring Editor
- JSON import/export

### 6. 最初からブランドUIを狙いすぎない

MVPでは、プロっぽさより操作の明快さを優先する。

やること:

- 余白を広めにする
- ボタンを明確にする
- 牌を見やすくする
- 編集項目を分かりやすくする

やらないこと:

- 過剰な演出
- 複雑なアニメーション
- 多色グラデーション
- 小さい情報密度の高いUI

## Match Screen Layout

スマホ前提の基本レイアウト。

```text
上: 相手3人のミニ状態
中: 自分の手牌
下: 引く / 捨てる / あがる
補助: 成立役・候補役・点数
```

## Tile Layout

```text
┌─────────┐
│         │
│   🦊    │  image / emoji / fallback
│         │
│ きつね  │  name
└─────────┘
```

## Editor Layout

Editorでは、初心者が迷わない入力順にする。

### Tile Editor

1. 名前
2. 絵文字
3. fallback label
4. カテゴリ
5. 枚数
6. ローカル画像

### Role Editor

1. 役名
2. 得点
3. 条件タイプ
4. 条件詳細
5. 説明

## Tone

- やさしい
- でも子どもっぽすぎない
- 作る楽しさを出す
- 公式文言で既存IP利用を煽らない
