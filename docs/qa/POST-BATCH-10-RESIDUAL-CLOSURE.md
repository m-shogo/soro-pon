## Closed / Mitigated Findings

### Records retention ordering

Set-like persisted arrays now remove duplicates before retention caps:

```text
roleCollection
achievements
recentMatchKeys
```

A duplicate-heavy prefix can no longer discard a later unique value merely
because slicing happened first. Raw over-limit payloads remain backed up when
storage permits.

### Match session identity

`MatchSession` is keyed by `matchSessionId`, not the bounded numeric gameplay
seed. A rematch therefore receives a distinct React component identity even if
a seed ever collides. The seed remains only a deterministic gameplay input.

### Editor validation parity

The live Deck Editor panel now uses `validateDeckForUse`, the same integrated
validator used at save/play/import boundaries. Nested IDs, duplicate
memberships, ignored group fields, contradictory score caps, and gameplay
feasibility are visible before save.

### Recovery export

TOP now exposes `退避データを書き出す` before destructive reset.

```text
exports only known *.corrupt-backup keys
preserves raw strings without JSON reinterpretation
uses a versioned bundle format
continues when one key cannot be read
never deletes the source backup
reports file-creation failure instead of claiming success
reset confirmation points to export first
```

Automatic restoration is intentionally absent. Copying raw corrupt text over
active data would be less safe than the current export-for-inspection path.

### Runtime skin trust boundary

Manifest `origin` is no longer sufficient to establish package trust.
`createSkinLoader` supplies an origin classification determined outside the
manifest, and validation rejects disagreement. An external source cannot
self-declare `official` to regain SVG privileges.

This is runtime trust classification, not cryptographic package identity. A
future external installer/marketplace still needs source binding, signature,
entitlement, revocation, and rollback design.

### CI supply-chain hardening

Main CI and Integrity workflows now pin setup actions to immutable release
commit SHAs:

generated by the exact supported Python/platform resolver.
