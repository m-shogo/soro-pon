# First Run and Playtest Loop

## Purpose

ユーザーが最初に迷わず遊び始め、作ったデッキを試し、結果を見て直し、また遊ぶ導線を固定する。

## Core Decision

```text
このゲームの継続体験は「作る → 試す → 結果を見る → 直す → また遊ぶ」の循環にする。
```

## First Run Flow

初回起動では、いきなり空のEditorに入れない。

推奨導線:

```text
1. TOP
2. まず遊ぶ / デッキを作る / JSONを読み込む
3. まず遊ぶなら公式サンプルでMatch Setupへ
4. デッキを作るならテンプレート選択へ
5. 1局終わったらResultからDeck Editorへ誘導
```

## Official Starter Deck

MVP公式サンプルは安全テーマ。

固定:

```text
動物スターター
```

理由:

- 既存IPリスクがない
- カテゴリが分かりやすい
- 子どもにも伝わる
- 色分けしやすい

## Deck Template Flow

新規デッキ作成時は、空白開始だけにしない。

選択肢:

```text
空のデッキ
動物テンプレート
スポーツテンプレート
旅行テンプレート
学校/クラス風テンプレート
```

MVPでは最低限:

```text
空のデッキ
動物テンプレート
```

## Playtest Loop

Deck Editorからすぐテスト対戦へ行けるようにする。

```text
Deck Editor
↓
[このデッキでテスト]
↓
Match Setup
↓
Match
↓
Result
↓
[デッキを調整]
↓
Deck Editorの該当タブへ戻る
```

## Result to Editor Feedback

Resultから戻る時、何を直すべきか出す。

例:

```text
この役が強すぎるかも: 2枚役 80点
特殊役が多く発動しました: 4件
ロン可能役が多めです: 23件
オールマイティ使用で高得点になりました
```

Resultのボタン:

```text
[もう一局]
[デッキを調整]
[この役を編集]
[特殊役を追加]
[バランスを見る]
[コレクションを見る]
```

## Editor Return Target

ResultからEditorに戻る場合、該当箇所へ直接移動する。

```text
上がり役が強すぎる → 上がり役タブ
特殊役が多すぎる → 特殊役タブ
点数が高すぎる → バランスタブ
牌が偏る → 牌タブ
カテゴリ色が見づらい → カテゴリタブ
```

## Autosave

Deck Editorでは自動保存を入れる。

```text
変更後に下書き保存
明示的な[保存]で確定
未保存で戻る時は確認
```

MVPではlocalStorageでよい。

## Undo

最低限、直前操作のUndoを用意したい。

MVPで入れるなら:

```text
牌削除
役削除
カテゴリ削除
```

削除操作はUndoまたは確認ダイアログ必須。

## Empty State UX

空状態を放置しない。

### 牌がない

```text
まだ牌がありません
[牌を追加]
[まとめて入力]
[テンプレートから追加]
```

### 役がない

```text
まだ上がり役がありません
[カテゴリから役を作る]
[3枚セット役を作る]
[テンプレートから追加]
```

### カテゴリがない

```text
カテゴリを作ると牌が見やすくなります
[カテゴリ追加]
[色付きカテゴリを自動作成]
```

## Suggested Fixes

Balance Checkは警告だけでなく、修正案を出す。

例:

```text
2枚役が高すぎます
推奨: 10〜40点
[40点にする]
[この役を編集]
[無視]
```

```text
カテゴリ色が似ています
[別の色を提案]
[カテゴリを編集]
```

## Final Decision

- 初回は公式サンプルで遊べるようにする
- 新規作成はテンプレートから始められるようにする
- Deck Editorから即テスト対戦できるようにする
- Resultから該当Editorタブへ戻れるようにする
- Balance Checkは修正案を出す
- Empty Stateには必ず次のアクションを出す
- Deck Editorは自動保存を持つ
