# Pre-UI Implementation Master Gate

## Purpose

This is the final gate before Soro-pon enters full UI implementation.

It collects the hard design decisions that must be respected so the game does not break when:

- roles increase
- custom decks become complex
- wildcards appear in multiple copies
- candidates overlap
- discard choices become unclear
- beginner users need help
- advanced users want details
- local data or imported JSON changes over time

## Must Not Start Full Match UI Until

The following are represented in types, pure functions, or tests:

```text

Role condition grammar
HandAnalyzer
WildcardResolver
WaitAnalyzer
IntentRanker
ExplainEngine
HandSorter
InsightEngine
Discard impact preview
ScoreCalculator
Match state machine
Result score breakdown
Local storage recovery
Import/export validation
```

## Core Non-negotiables

```text
The UI must not own rule truth.
The UI must not calculate score.
The UI must not decide if a role is complete.
The UI must not assign wildcard meaning.
The UI must not guess player intent.
The UI must not mutate state during preview.
```

Domain functions produce facts.
Insight functions summarize facts.
UI renders facts.

## Candidate Handling

Role candidates must be generated by the engine and classified as:

```text
completed
tenpai
near
bonusOnly
invalidButExplainable
```

Normal play shows only compressed facts:

```text
primary candidates: up to 3
primary insights: up to 2
hidden candidate count: required when compressed
```

## Wildcard Handling

MVP standard:

```text
multiple wildcards may exist in hand
one win_role uses max 1 wildcard by default
one set/group uses max 1 wildcard by default
discarded wildcard ron is blocked by default
wildcard assignment is candidate-specific
wildcard assignment is not permanent until final result
```

## Discard UX

Discard preview must answer:

```text
what candidate is kept
what candidate is broken
what candidate improves
what wait changes
what wildcard assignment changes
```

Discard preview must not mutate match state.

## Insight UX

InsightEngine must show board facts, not instructions.

Allowed:

```text
This discard breaks Animal Trio
One tile away: Bird category
This bonus cannot win alone
```

Forbidden:

```text
Best move
Correct discard
You should aim for
```

## Beginner / Advanced

Beginner and advanced modes are display modes only.

They never change rules.

Beginner:

```text
one top candidate
one wait
one insight
simple action state
```

Advanced:

```text
top 3 candidates
discard impact table
wildcard alternatives
score breakdown
detail panel
```

## Deck Author Guardrails

Deck editor must warn about UX-breaking designs:

```text
no win_role
conditionless role
impossible role
role overlap
wildcard-dependent role
similar role names
too many close candidates
too easy high-score role
bonus-only role that looks like win_role
long role name
missing role explanation
```

## Match State Guardrails

Match flow must use a strict state machine.

Required state concepts:

```text
setup
deal
turnStart
draw
afterDrawAction
discardSelect
reactionRon
turnEnd
roundEnd
result
```

Actions must validate current state.

## Result Trust

Result must explain:

```text
selected win_role
why it won
wildcard assignments
special bonuses
ScoreBonus items
total score
coins
collection updates
```

No hidden scoring in UI.

## Performance Guardrails

Analyzer should be deterministic and bounded.

Required guard concepts:

```text
candidate output cap
wildcard branch cap
role count warning
analysis warning when capped
deterministic ranking tie-breaks
```

If analysis is capped, UI must show a warning instead of pretending the answer is complete.

## Implementation Order Reminder

Correct order:

```text
schema
validation
domain types
role condition grammar
role analysis
wildcard analysis
wait analysis
ranking
explanation
insight
discard preview
score
state machine
storage/import
UI foundation
full screens
```

Wrong order:

```text
pretty Match UI first
then add rules later
```

## Final Decision

Soro-pon should be built from tested domain facts outward.

If implementation pressure appears, cut UI decoration first.

Do not cut:

```text
rule determinism
candidate explanation
wildcard constraints
discard preview purity
state machine correctness
score transparency
```
