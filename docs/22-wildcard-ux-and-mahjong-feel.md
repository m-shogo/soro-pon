# Wildcard UX and Mahjong-like Feel

## Purpose

オールマイティ牌の扱いと、対戦中のUI/UX方針を固定する。

結論:

```text
オールマイティは基本自動割当。
必要な時だけプレイヤーが手動変更できる。
対戦中の気持ちよさは麻雀アプリに寄せる。
```

## Core Decision

オールマイティ牌を毎回クリック選択式にしない。

悪い体験:

```text
ビブルカードを引く
↓
毎回「何として使いますか？」を聞かれる
↓
テンポが止まる
↓
麻雀アプリの気持ちよさから遠ざかる
```

良い体験:

```text
ビブルカードを含む手牌を持つ
↓
アプリが一番得する候補を自動表示
↓
[あがる] / [ロン] を押せる
↓
詳細を見たい時だけ手動変更できる
```

## Default Wildcard Behavior

MVPでは以下を基本にする。

```text
1. 最高点のwin_roleが成立するように自動割当
2. 同点ならspanが大きい役を優先
3. さらに同点ならrole定義順を優先
4. special_bonusはあがり成立後に高点順で評価
5. score_bonusには原則使わない
```

## Manual Override

手動選択は常時出さない。

出す場面:

```text
・複数の上がり候補があり、プレイヤーが確認したい時
・Result前に「内訳を見る」を開いた時
・Editorのテスト判定画面
・デバッグ/検証モード
```

対戦中の通常導線では、以下のようにする。

```text
候補バー:
ビブルカード → ゾロ扱いで成立
[あがる] [内訳]
```

`内訳` を押した時だけ、手動変更UIを表示する。

```text
ビブルカードを何として扱う？
[ゾロ] [サンジ] [ロー] [変更しない]
```

## Do Not Interrupt Flow

以下は禁止。

```text
・ビブルカードを引いた瞬間に選択モーダルを出す
・捨てるたびにオールマイティ確認を出す
・special_bonusだけのために対戦中モーダルを出す
・score_bonusのために選択させる
・毎ターン候補を全表示する
```

## Mahjong App Feel

対戦画面の気持ちよさは麻雀アプリを参考にする。

重要なのは、麻雀そのものに寄せることではなく、以下の操作感。

```text
・牌を見てすぐ状況が分かる
・押せるボタンだけ光る
・ロン/あがりの瞬間が気持ちいい
・確認モーダルが少ない
・捨て牌が読みやすい
・直近の捨て牌が強調される
・自分の手牌が一番大きい
・相手情報は邪魔しない
```

## Button UX

### Draw / 引く

- 自分のdraw phaseだけ押せる
- 押したら牌が手牌に入る
- 引いた牌は少し強調する

### Discard / 捨てる

- 牌を1枚タップして選択
- 選択牌が少し浮く
- [捨てる] ボタンが有効になる
- 再タップで選択解除

### Win / あがる

- win_role成立時だけ強調
- オールマイティ使用時は小さく表示

```text
あがれます: 三兄弟
ビブルカード → サボ扱い
```

### Ron / ロン

- 他プレイヤーの捨て牌でwin_role成立時だけ出す
- 直近の捨て牌を光らせる
- special_bonus / score_bonus では出さない

```text
ロンできます: 船長と剣士
[ロン] [パス]
```

### Pass / パス

- reaction phaseだけ出す
- 迷わせないため小さくてもよいが押しやすくする

## Candidate Bar

役候補は大きなパネルにしない。

```text
下部または中央下に小さな候補バー
```

表示例:

```text
あと1枚: 三船長 / Dの意志
成立: 船長と剣士
ビブルカード: ロー扱い
```

表示優先:

1. あがれる役
2. ロンできる役
3. あと1枚の役
4. オールマイティ使用内容
5. special_bonus候補

special_bonus候補は控えめに表示する。

## Wildcard Result Display

Resultでは必ず表示する。

```text
オールマイティ使用
・ビブルカード → ローとして使用
```

special_bonusに使った場合も表示する。

```text
特殊役
・三船長 +80
  ※ ビブルカードをキッドとして使用
```

## Manual Override UI

手動変更UIは、対戦中の主導線ではなく補助導線。

表示内容:

```text
オールマイティ牌
現在: ビブルカード → ロー

候補:
[ロー]
[キッド]
[サボ]
[使わない]
```

制約:

- 候補は成立可能なものだけに絞る
- 候補を出しすぎない
- 役ごとに1枚まで
- 変更後の点数を即表示する

```text
ローにする: 三船長 70点
キッドにする: 三船長 70点 + 特殊役 80点
```

## Implementation Policy

MVPでは以下でよい。

```text
自動割当のみ
Resultで使用内容を表示
手動変更UIは後回し
```

ただし、DBと評価結果には手動変更できる余地を残す。

```ts
type WildcardAssignment = {
  wildcardTileInstanceId: string;
  usedAsTileId?: string;
  usedAsCategory?: string;
  roleId: string;
  source: 'auto' | 'manual';
};
```

## Final Decision

- オールマイティは基本自動割当
- 毎回クリック選択式にはしない
- 手動変更は「内訳」や検証画面だけ
- 麻雀アプリのようにテンポを止めない
- 押せるボタンだけ強調する
- あがり/ロンの瞬間を気持ちよくする
- Resultでオールマイティ使用を明示する
